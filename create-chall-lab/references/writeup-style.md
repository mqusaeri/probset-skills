# Writeup style

Write every facilitator document in Bahasa Indonesia, from your own verified run.

| Format | Written by hand | Generated by the item's script |
|---|---|---|
| Jeopardy | `writeup.md`, steps match `solve.py` | |
| Attack-Defense | `writeup.md`: vuln, exploit idea matching `exploit.py`, fix matching `patch/fix.patch` | |
| KOTH | `writeup.md`: foothold, privesc, how a king defends. `rules.md` for teams | |
| Cyber Drill machine | `walkthrough.md` (facilitator), `brief.md` (participants, zero spoilers) | |
| Cyber Drill blue | `brief.md`, plus `note` fields in `timeline.json` | `facilitator/answer-key.md`, `facilitator/timeline.md` |
| TTX | `facilitator_notes` in `scenario.json` | `facilitator/guide.md` |

The rules below are for Jeopardy writeups. They apply in spirit to every hand-written document:
match the real run, no fake struggle, root cause, mitigation, fictional names only.

`writeup.md` is read by other participants after the event and by the facilitator during review.
Write it from the point of view of someone solving the challenge for the first time.

## Rules

- **Match the real solve.** Every step in the writeup is a step `solve.py` takes, in the same
  order. If you changed the solver, update the writeup.
- **Easy has about 2 steps, Medium 3 to 4.** If the count does not match the level, change the
  level or the challenge.
- **Show what the solver sees.** For each step: what you tried, the request you sent, and the part
  of the response that tells you it worked. Short snippets only.
- **Do not fake struggle.** If the path is straightforward, write it straight. Mention a dead end
  only if the challenge really has one.
- **Explain the root cause** in one short paragraph: which input is trusted, and why that is wrong.
- **End with mitigation** that a developer could apply to the fictional app.
- **Keep it fictional.** Use the invented app and organisation names only.
- About one page. No walls of tool output.

## Template

```markdown
# <Judul Soal>

- Level: Easy | Medium
- Kelas bug: <nama> (CWE-xxx)
- Sumber ide: <CVE, berita, riset, atau ide sendiri, satu baris>

## Cerita

<Dua sampai tiga kalimat soal app fiktifnya dan apa yang dicari pemain.>

## Langkah solve

1. <Apa yang dicoba, request yang dikirim, dan tanda berhasilnya.>
2. <...>

## Akar masalah

<Input mana yang dipercaya begitu saja, dan kenapa itu salah.>

## Mitigasi

- <Perbaikan konkret di kode app.>
- <Kontrol tambahan, misalnya validasi, allowlist, atau prinsip least privilege.>
```
